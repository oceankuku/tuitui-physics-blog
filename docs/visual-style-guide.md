# 统一视觉规范（2026-10-22 建立）

> 总规范第十二节要求：先建立全系列样式，再用真实文章验证。本文件是网页端与公众号复制的视觉基准；移动端起始方案为正文 16–17px、行高 1.7–1.9，**最终以公众号预览为准**。

## 一、字号与行高

| 元素 | 网页端 | 公众号复制产物 |
| --- | --- | --- |
| 正文 | 16–17px | 16px（行高 1.75，现状保持） |
| 一级小节（##） | 22–24px | 20–22px，加粗 |
| 二级小节（###） | 18–20px | 17–18px，加粗 |
| 题干卡 | 同正文 | 同正文，楷体灰底 |
| 答案卡 | 同正文 | 同正文，楷体绿底 |
| 图注/说明 | 13–14px | 14px，居中或左对齐统一 |
| 表格 | 14–15px | 14px |

## 二、需统一的元素清单

每项在模板中定死，新文章不另行发挥：

1. **标题层级**：正文不写 H1；## 与 ### 两级足够，层级不跳。
2. **正文与图注**：图注紧贴图片下方，格式统一「图 X｜说明文字」或纯说明句，全站一致。
3. **题干、答案、解析**：`:::problem` 楷体灰底、`:::answer` 楷体绿底、`:::note` 琥珀色——沿用现有渲染，不自改配色。
4. **留白与段间距**：段间距由渲染管线控制，正文不手敲空行堆间距。
5. **公式对齐**：多步推导按逻辑分行居中；**长公式按推理分行，不通过过度缩小字号解决**。
6. **图片边距**：图片块级居中，宽 100% 上限，上下留一行呼吸空间。
7. **表格样式**：`table-layout: fixed`（复制管线已有），列数控制 3–5 列，过宽拆表或改列表；数值、单位、小数位、对齐规则全表统一。
8. **配色与强调**：克制用色；加粗只用于关键条件、结论、易错点；**重要信息不能只依赖颜色**（色盲可读）。

## 三、公式显示

- 公式优先保持**可编辑与清晰显示**（文本渲染）。
- 平台必须转图片时（公众号特殊场景）：保留公式源文件，检查分辨率、背景、边缘裁切和手机可读性。
- 分数竖式、根号画法沿用现有渲染器（inline-block 方案 + 1.22em 放大根号），**任何语法迁移先在小范围验证，不直接全站替换**。

## 四、移动端检查基准

- 目标宽度：**约 360–430 CSS 像素**（主流手机竖屏）。
- 检查项：正文无横向溢出；表格不撑破容器；公式不截断；图片不超宽；代码块可横向滚动且不影响页面。
- 检查工具：浏览器开发者工具设备模拟 + 真机微信公众号预览。

## 五、验收口径

- **网页渲染**与**公众号实际粘贴效果**分别验收，**网页截图不能替代公众号预览**。
- 无法取得实际预览时，在台账或文章备注中**明确记录"公众号效果未验收"**，不虚报通过。
- 每类版式元素（题卡、公式块、表格、多图段落）至少有一次真实粘贴验证记录后，才可标记"公众号已验收"。
